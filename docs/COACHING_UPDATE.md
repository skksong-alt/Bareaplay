# BareaPlay 코칭 업데이트 (2026-09-16)

## 사용 순서

1. 회원은 기존 `?vote=current` 링크로 참석 신청한다. 한국어/English 전환과 게스트·대리 신청을 지원한다. 이미 참석한 사람이 다시 참석을 눌러도 기존 선착순·대기 상태를 유지한다.
2. 지난 경기 활약 투표는 참석 화면 아래에서 한다. 기존 `ratings/{date}.votes`의 3·2·1점 방식을 유지하며 참석 신청의 필수 단계가 아니다. 이번 주 불참자도 지난 경기에 참여했다면 평가할 수 있다.
3. 모임배포 탭 아래 **이번 주 목표·영상·지난 경기 투표**에서 대상 날짜를 선택하고 불러온다. 한·영 문구, YouTube/FIFA URL, 추천 구간, 현장 연습을 편집하고 미리보기 후 저장한다. 미설정 날짜에는 검토한 FIFA 자료 4개가 날짜 기준으로 주간 순환한다. 실시간 영상 검색이나 외부 AI 예약 작업은 실행하지 않는다.
4. 평가 날짜를 비워 두면 대상 경기 이전이면서 오늘 이전인 가장 최근 저장 배정일을 선택한다. 경기 취소·휴무가 있으면 실제 진행한 경기 날짜를 명시하거나 숨기기를 선택한다. 자동 판단은 실제 개최를 확인하는 기능이 아니다.
5. 선수관리 탭 아래 **선수 역할·게스트 정보**에서 연결·수비 정리·전방 연결·안내·학습 역할과 안내 선수를 지정한다. 역할 정보는 감독이 입력하며 성격을 자동 추측하지 않는다. 게스트 임시 능력치·포지션은 지정 날짜에만 사용한다. 등록 선수의 기존 능력치·회비 유형은 바꾸지 않는다.
6. 라인업 탭 **감독 보드**에서 팀 배정 탭의 선택 날짜를 불러온다. 최근 4회 배정 이력, 팀 고정, 쿼터별 포지션 고정, 부분 재배정 미리보기, 상대 비교를 사용한다.
7. 미리보기는 저장하지 않는다. 출전/GK/희망 기회와 변경 목록을 확인하고 **이 후보 적용·저장**을 누르면 그 날짜의 해당 팀 라인업을 기존 저장 경로로 반영한다. 명단이나 라인업이 미리보기 이후 바뀌면 재생성을 요구한다.
8. 팀을 새로 나누려면 기존 포지션 고정을 먼저 해제한다. 고정 팀 인원이 과도하거나 팀 수가 달라 조건을 만족할 수 없으면 배정을 중단한다. 함께/분리·안내 조합을 동시에 만족하지 못하면 적용 전에 확인한다.
9. 수동 수정 이유 기본값은 **오늘만 팀 사정**이다. **지속적으로 적합한 역할**로 표시한 조정만 반복 성향 제안에 이용한다. 기존 이유 없는 조정 기록은 그대로 보존하지만 영구 성향 추론에서는 제외한다.
10. 공유 결과의 각 쿼터에서 **이번 쿼터 역할**을 펼치면 선수별 임무를 한·영으로 볼 수 있다. 기존 공유 링크의 스냅샷도 계속 읽는다. 이미 배포된 공유 결과를 새 배정으로 갱신하려면 기존처럼 새 공유 링크를 생성해야 한다.

## 판단 기준과 한계

- 최근 4회는 저장된 라인업에 등장한 최근 4개 날짜다. 실제 출전 시간이나 경기 종료 확인 기록은 아니다. 심판 횟수는 휴식에 포함된다.
- 희망 포지션 기회가 적은 선수에게 추가 가산점을 준다. 희망 횟수는 최적화 목표이며 모든 조합에서의 확정 보장은 아니다.
- 팀 배정은 기존 능력치·포지션·인원 평가에 역할 분산과 안내 조합을 추가한다. 게스트도 처음부터 최적화에 참여한다.
- 상대 비교는 선택한 두 팀의 같은 쿼터별 능력치 평균과 등록된 역할을 보여준다. 실제 대진이 다른 쿼터는 팀 선택을 바꿔 비교한다. 승률 예측이 아니다.
- 포지션 분류는 포메이션을 반영한다. 예: 4-3-3의 RW는 공격, 4-4-2와 3-5-2의 RW는 미들로 집계한다.
- 교육 자료는 성인 초보팀을 위한 실천 예시다. 원본 FIFA 자료에는 유소년 대상 세션이 포함된다. 준비운동 후 공간·압박·인원을 참가자에 맞게 조절한다.
- 프로필에는 공개 가능한 축구 역할만 입력한다. 비밀 메모나 의료·성격 평가 저장소로 사용하지 않는다.

## 데이터 보존

- 배포나 페이지 열기만으로 기존 운영 문서를 수정하는 초기화·이관 작업은 없다.
- 기존 `players`, `attendance`, `expenses`, `incomes`, `votes`, `dailyMeetings`, `shares`, `matchRecords`, `ratings`의 ID와 필드 의미를 유지한다.
- 새 콘텐츠·역할·고정은 `coachWeeks`, `coachPlayers`, `coachPlans`에 저장한다. 부분 적용 이력은 `coachAdjustments`에 추가한다. 기존 `adjustLogs`의 새 조정에는 선택한 `reason`만 추가한다.
- 기존 회계·출석 저장 및 삭제 기능의 코드는 변경하지 않았다. 새 코칭 기능에는 해당 컬렉션 쓰기 경로가 없다.
- 기능 도입 전 데이터 마이그레이션이나 백업 복원은 필요하지 않다. 기능을 되돌려야 할 경우 신규 코칭 문서를 보존하고 별도 승인된 수정 커밋으로 이전 UI를 복구할 수 있다. 기존 데이터의 reset/revert나 일괄 삭제는 하지 않는다.
- 기존 Rules의 최상위 컬렉션 관리자 쓰기 규칙을 사용한다. Rules·프로젝트 설정은 변경하지 않는다. 신규 문서 권한 오류 시 기능은 오류를 표시하며 임의로 우회하지 않는다.

## 검증 방법

- `node --test tests/coachCore.test.mjs`: 실제 라인업 생성기를 포함한 순수 로직 테스트. Firebase 연결 없음.
- `node --check <파일>`: JavaScript 구문 검사.
- `node tests/browser-smoke.cjs`: Playwright와 설치된 Edge 사용. `playwright`가 설치된 Node 모듈 경로를 `NODE_PATH`에 지정한다. 모든 Firebase SDK를 메모리 가짜 저장소로 대체하고 나머지 외부 요청도 차단한다. 운영 키나 테스트용 운영 문서를 요구하지 않는다.
- 브라우저 검사 범위: 모바일 한·영, 게스트 신청, 다른 사람의 이전 표 보존, 초기 로드의 쓰기 없음, 역할·주간 편집, 고정 저장/해제, 부분 미리보기/적용, 자동 팀 배정, 회계·출석 원본 보존.
- 캐시 v59, app v15. 변경 모듈 URL과 Service Worker 목록을 함께 갱신했다. 기존 탭은 새 버전 안내 후 새로고침하여 갱신한다.
