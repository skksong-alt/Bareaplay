## 구현된 부분

- 이전 작업의 활약투표 화면 노출 완화: 개인별 원본 읽기·자동 선택 복원·실시간 집계를 제거하고 제출 후 선택을 지운다. 서버 읽기 권한 차단은 별도 승인 대기이며 완전한 비공개 해결로 표현하지 않는다.
- 등록 명단에 없는 이름은 참석/미정/불참 저장 전에 게스트 여부를 확인한다. 취소하면 쓰기 요청을 보내지 않는다.
- 참석/대기는 `attendingSince`, 미정/불참은 `updatedAt`의 서버 시각으로 정렬한다. 초와 나노초를 비교한다. 공개 화면·관리자 화면·새 공유 스냅샷에 같은 정렬기를 사용한다.
- 응답은 이름 문서에 저장되는 기존 구조를 유지한다. Firestore 문서 목록 자체의 물리적 순서를 보장하는 방식이 아니다. 완전히 동일하거나 없는 시각은 이름 순으로 안정적으로 표시하며, 시각 없는 참석자는 의무 배정 시 임의 순번을 부여하지 않는다.
- 심판은 전체 명단의 늦은 참석 신청순으로 순환한다. 해당 팀에 휴식 자리가 없으면 가능한 다음 사람을 택하고 사유를 표시한다. 모두 출전 중이면 외부 심판 필요를 알린다.
- 키퍼/휴식은 각 팀의 늦은 참석 신청순 큐로 순환한다. 해당 쿼터의 심판을 먼저 제외하고 키퍼, 나머지 휴식을 선택한다. 전담 GK(기존 주/부 포지션 모두 GK)는 예외다. 능력치·일반 GK 선호·희망 포지션은 이 순번을 바꾸지 않는다.
- 배정 직전에 해당 날짜의 참석 응답 시각을 다시 읽는다. 투표 선택이 모호하거나 참석 시각이 없는 선수가 있으면 중단한다. 명단 textarea의 편집 순서를 투표 시각 대신 사용하지 않는다.
- 포지션 고정과 드래그로 의무 순번을 바꾸지 못하게 한다. 새 공유 시 현재 투표 순번과 다른 기존 라인업은 자동 수정하지 않고 재생성을 안내한다. 저장된 과거 배정을 화면에 표시하는 것만으로 공동 심판을 다시 계산해 덮어쓰지 않는다.
- 운영자 경기 준비 안내, 작업일/투표일 불일치 표시, 단계별 이동을 추가했다. 공개 단계 이동 자체는 배포/공개를 실행하지 않는다.
- 라인업은 기본적으로 한 쿼터씩 표시하며, 쿼터 선택과 전체 보기로 전환한다. 감독의 최근 이력·부분 재배정 도구는 기본 접힘 상태로 둔다.

- 최근 조합 반복 회피는 기본 해제한다. 이는 8주간 팀/필드 역할을 완전히 자동 유지하는 기능까지 구현했다는 뜻은 아니다.

- 활약투표 원본의 서버 읽기 권한 제한 및 다른 이름으로 표를 바꾸는 문제의 근본 해결.
