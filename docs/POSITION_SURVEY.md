## 팀원 사용법

- 공유 주소: https://bareaplay.vercel.app/?preferences=1
- 참석 페이지의 희망 포지션 링크에서도 들어온다. 감독용 선수관리 화면에는 공유 설문 열기와 응답·수요 조회가 있다.
- Google 로그인 후 팀에 등록된 본명을 선택한다. 계정 표시 이름을 본명으로 자동 간주하지 않는다.
- 경기장 그림에서 1·2지망을 고른다. 같은 자리 선택도 가능하며 두 표로 집계하지 않는다.
- 본인은 같은 Google 계정으로 다시 방문해 응답을 수정할 수 있다. 최초 선택한 본명은 고정한다. 잘못된 이름/다중 계정은 감독에게 문의하도록 안내한다.
- 다른 팀원에게 답이 공개되지 않는다. 전체 조회는 지정된 감독 계정만 허용한다. 일반 관리자 역할만 있다고 전체를 볼 수 있는 것은 아니다.

## 설문 상단 설명

빈번한 팀·역할 변화로 같은 움직임을 반복하고 동료와 호흡을 맞추기 어려운 점을 설명한다. 목적은 자리를 영구 고정하는 것이 아니라 개인의 기본기·판단·역할 이해와 팀워크를 기르는 것이다.

먼저 희망을 조사하고, 감독이 포지션 수요·팀 균형을 보고 8주 동안 주 역할과 팀 조합을 가능한 한 유지한다. 참석 인원·결원·역할 적합성에 맞는 조정은 허용하며, 시작일과 배정은 감독이 별도 공지한다. 마지막에는 선수 의견과 학습 결과를 검토한다. 상세 계획은 접어서 화면 길이를 줄였다.

희망 배정은 보장하지 않으며 기존 선수 평가/배정을 자동 변경하지 않는다. 심판은 전체, 키퍼·휴식은 팀별 늦은 참석 신청순이며 전담 키퍼 예외는 유지한다.

## 권한과 데이터 보존

- 기존 승인 구조 `privatePositionPreferences/{auth.uid}`와 기존 7개 필드를 유지한다. 기존 players·회계·출석·참석투표·라인업 쓰기는 없다.
- Google provider, 문서 UID 일치, 등록 선수 이름 존재, 포지션 허용값, 필드 종류/개수, 서버 시각, 최초 이름 유지 조건으로 create/update를 제한한다. delete는 모두 거부한다.
- 포괄 규칙의 읽기·쓰기 양쪽에서 새 컬렉션을 제외한다. 활약투표 원본 비공개 규칙도 그대로 유지한다.
- 지정 감독 UID는 Console의 로그인 계정과 Authentication 사용자 행을 대조해 사용하며 Git이나 문서에 저장하지 않는다. 적용 조각은 `POSITION_SURVEY_RULES_DRAFT.txt`에 있다.
- 운영 테스트 응답은 생성하지 않는다. 문제 발생 시 기능만 닫고 새 응답과 기존 데이터는 보존한다. 공개 읽기를 복구 방법으로 사용하지 않는다.

## 함께 반영한 활약투표 표시 개선

큰 이름 기억 체크박스를 없앴다. 기본 자동 기억을 유지하고 작은 켜기/끄기 버튼으로 공용 기기에서 해제한다. 기존에 해제한 기기의 설정은 존중한다. TOP 3는 금·은·동메달과 1·2·3위로 표시하며 동점은 기존 이름순 규칙을 명시한다. 서버 집계·점수·저장 구조는 변경하지 않는다.

## 확인 범위와 남은 제한

- 로컬 격리 브라우저: 로그인 전 목적 설명, 한·영 전환, 본명 선택, 같은 지망, 재방문 수정, 자기 응답 경로만 접근, 기존 선수 보존, 320px 가로 넘침을 확인했다. Firebase와 외부 요청은 가짜 저장소로 대체했다.
- 이름 기억 해제 유지, 메달/순위, 재투표 취소, 원본 미조회에 대한 격리 활약투표 검사도 통과했다.
- Rules Playground에서 익명 조회 거부, 일반 사용자 자기 문서 조회 허용, 타인 조회 거부, 지정 감독의 타인 문서 조회 허용을 확인했다. Playground에는 list 시뮬레이션이 없어 list는 규칙 조건을 검토했다.
- 규칙 게시 후 실제 익명 REST 조회로 존재하지 않는 설문 문서와 활약투표 문서의 HTTP 403을 확인했다. 문서를 작성하거나 실제 응답 내용을 출력하지 않았다.
- 실제 Google 팝업 로그인 완료와 운영 응답 저장은 팀원이 직접 확인해야 한다. 운영 테스트 제출은 하지 않았으며 쓰기 성공을 실증했다고 표현하지 않는다.
- Google 계정은 실명을 증명하지 않는다. 중복 이름/다중 계정 응답은 감독 화면에서 표시하며 확인 전 집계에서 제외한다.
- 8주 역할 유지가 자동으로 강제되는 기능은 아니다. 설문 집계를 배정에 자동 반영하지 않는다. 전체 운영자 UI 정리는 다음 별도 작업이다.

## 후속 화면 개선 — 로컬 수정, 배포 전

- 경기장 표시를 4-2-3-1의 11개 자리로 정리했다. 중앙 미드필더(CM)와 수비형 미드필더(DM)는 같은 줄이다. 두 CB 버튼은 모두 기존 `CB` 선호로 저장되며 좌우 선호를 새로 구분하지 않는다. 기존 응답 코드와 집계 구조는 그대로다.
- 서로 다른 두 자리 선택과 같은 자리 집중 선호를 큰 안내 문구로 구분한다. 별도 '2지망도 같은 자리' 버튼 없이 같은 포지션을 다시 누르면 된다. 두 지망은 경기장에 동시에 표시한다.
- 역할 유지/유연성 체크박스를 제거하고 선택 입력인 '감독에게 전할 말'만 남겼다. 기존 Rules와의 호환을 위해 `stable`, `flexible` 필드는 유지한다. 기존 응답 수정 시 저장된 값을 보존하고 새 응답은 두 값을 false로 저장한다. 더 이상 이 값을 선수 의사로 표시하거나 판단하지 않는다.
- 첫 제출 이후 본명을 고정하는 동작과 본인 응답 수정은 유지한다. Firebase 데이터 이관·수정, Rules 변경은 없다.
- 수정 기능만 로컬 가짜 저장소에서 확인하며 운영 Firebase에 테스트 응답을 제출하지 않는다.
