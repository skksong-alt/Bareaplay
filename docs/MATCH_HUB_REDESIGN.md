# 참석·모임 화면 개편 — 로컬 검증 기록

2026-09-16, 기준 커밋 `7537427`, `master`. 아래는 로컬 검증 당시 기록이다. 검증 당시 commit, push, 배포 또는 운영 Firebase 쓰기를 수행하지 않았다. 이후 사용자 승인으로 이 개편의 GitHub 반영 및 Vercel 운영 배포를 진행한다. 배포 작업에서도 운영 Firebase 쓰기 테스트는 수행하지 않는다.

## 사용자 화면

- PC: 참석 신청·모임정보 / 참석 현황의 2열. 휴대폰: 신청 → 현황 → 경기 준비자료 순서.
- 밝은 카드, 짙은 녹색 포인트와 낮은 대비의 CSS 축구장 워터마크. 원격 이미지나 추가 추적 SDK 없음.
- 현황: 상태별 인원수, 번호가 있는 참석 명단, 별도 대기·미정·불참 표시.
- 경기 준비자료는 기본 닫힘. 핵심 제목 자체가 외부 영상 링크이며 URL 문자열을 본문에 노출하지 않는다. 15분 연습 유지.
- 이름 입력란 옆 활약투표 링크 → 별도 주소 `?voteId={id}&review={date}`. 평가 대상 날짜가 표시되고 원래 참석 투표로 돌아간다. 이름 초안은 해당 투표별 sessionStorage, 언어는 기존 localStorage 설정을 사용한다.
- 활약투표 화면의 '지난 경기 영상'은 사용자 제공 FC바레아 유튜브 채널로 새 탭 이동한다. 특정 경기 영상 자동 매칭이 아니며 날짜를 찾아보도록 안내한다.
- 기존 공유 보드의 잘못된 '다음 경기' 고정 링크 제거. 기존 `shareId` 링크와 저장된 공유 문서는 유지.

## 관리자 흐름

- '참석·모임정보' 탭 안에 투표 생성, 장소 선택, 참석 현황 및 라인업 확정·공개를 통합.
- 기존 `locations`의 장소 이름과 지도 링크를 재사용. 투표의 `location`은 기존 문자열 그대로 저장한다.
- 공개 시 새 모임 입력란의 미저장 내용이 아닌, 현재 불러온 투표 정보를 사용한다.
- 투표 날짜와 팀 배정 날짜 불일치 / 최신 투표 정보 확인 실패 / 선택 변경 시 공개하지 않는다. 확인 대화상자를 거친다.
- 공개 시 기존 방식의 `shares` 신규 스냅샷 및 `settings/activeMeeting` 갱신은 유지. 기존 공유 문서·투표 응답·회계 자료는 삭제하지 않는다.

## 데이터 호환성 — 스키마 변경/마이그레이션 없음

- 기존 Firestore 컬렉션, ID, 필드 타입과 이름을 유지한다.
- 공개 결과 탐색: 기존 `shares.meetingInfo.time`을 경기 일시로 조회하고 장소 이름이 동일한 완성된 6쿼터 공개본 중 최신 생성본을 선택한다. 조회 실패와 '배정 전'은 구분한다. 다른 주의 `settings/activeMeeting`으로 대신 연결하지 않는다.
- 같은 일시·같은 장소에 별개의 두 투표를 만드는 경우까지 고유하게 구별하는 새 관계는 추가하지 않았다. 향후 영구적인 `voteId → shareId` 연결이 필요하면 별도 설계·승인이 필요하다.
- 기존 `coachWeeks.segmentKo`, `segmentEn` **문자열**에 `[지침](HTTPS 영상 주소)` 형식을 선택적으로 지원한다. 기존 일반 설명과 단일 자료 설정도 표시한다. 저장은 기존 관리자 저장 버튼을 누를 때만 기존 필드에 merge한다.
- 기본 추천 6개는 사용자가 제공한 Gemini 모음에서 가져온 정적 목록이다. 영상 내용을 독립적으로 확인한 요약이 아니며, 매주 자동 검색·교체하는 작업은 설정하지 않았다. 날짜별 관리자 편집은 가능하다.
- `ratings/{date}.votes.{name}` 및 `votes/{id}/responses/{name}`의 기존 merge 저장 경로 유지. 페이지 방문과 링크 클릭만으로 쓰기하지 않는다.

## 검증 및 배포 전 확인

- JavaScript 구문 검사, 순수 로직/콘텐츠/캐시 테스트.
- `tests/browser-smoke.cjs`: Firebase SDK를 인메모리 가짜 구현으로 대체하고 모든 외부 요청을 차단하는 브라우저 테스트. 익명 신청, 기존 참석 순번·회비 필드 보존, 마감 대기, 종료, 평가 후 복귀, 채널 링크, 장소 선택, 날짜 불일치 공개 차단, 기존 운영 기능 회귀를 검사한다.
- 320px·390px 모바일과 1440px PC 레이아웃 및 접힌/펼친 자료 화면 검사.
- 캐시 v60 / app v16 / 관련 모듈 버전과 캐시 목록 일치 확인. 새 CSS도 캐시 목록에 포함한다.
- 실제 운영 Firestore 권한·색인 상태, iOS Safari 및 설치된 PWA의 실기기 업데이트는 이번 로컬 검증의 범위가 아니다. 운영 데이터에 쓰는 테스트를 수행하지 않았다.
- 사용자 배포 승인 후 Git 변경 범위 확인 → commit/push → Vercel 성공 확인 → 기존 사용자 새 버전 반영을 읽기 전용으로 확인한다.
